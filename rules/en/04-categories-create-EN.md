# Categories: Creating & Assigning During Recipe Creation (EN)

## Principle

The category is the **shelf** a recipe sits on. It answers: *what kind of dish is this?*

Closed set, target size **10–20**. Growth is a defect signal: anyone creating the thirtieth category is almost always resolving a boundary problem the wrong way (§4).

> **A recipe gets one category, at most two.** If three seem necessary, either the axis is broken (§1) or two of them are really tags.

---

## 1. The axis rule

Every category must answer **the same question**. Two plausible axes compete:

- **Axis A — dish type / course:** Starter, Main, Side, Soup, Salad, Dessert, Baking, Bread, Sauce & Dip, Drink, Basics
- **Axis B — meal:** Breakfast, Lunch, Dinner, Snack

**Pick exactly one.** Mixing them gives every recipe two categories, breaks the shelf metaphor, and makes browsing useless.

**Recommendation: Axis A.** Dish type is a property of the recipe; meal is a property of how you use it — the same soup is a main at lunch and a starter at dinner. Meal then becomes a tag in the *Occasion* facet.

Document the chosen axis. Without a recorded decision the list drifts back into a mixture within months.

---

## 2. Assigning when creating a recipe

| Tier | Test | Action |
| --- | --- | --- |
| 0 | Dish type is unambiguous | assign the category |
| 1 | Recipe fits two categories | take the **dominant** one; add the second only if the dish genuinely is both (a soup served as a main) |
| 2 | Nothing fits, but an existing one is close | **take the existing one** — a slightly loose fit beats a new category |
| 3 | Genuinely nothing fits | leave the recipe uncategorised, send to review — do not create on the spot |

A recipe without a category is a clean intermediate state. A hastily created category is forever.

---

## 3. The creation test

Create a category only when **all three** hold:

1. **Axis.** It answers the same question as every existing one (§1).
2. **Volume.** It will hold **at least 15 recipes** within a year. Fewer → tag.
3. **Browse, not filter.** You want to browse it, not filter by it. Browsing = category, filtering = tag.

All three must hold. Point 2 is an estimate — when in doubt make it a tag, because a tag can be promoted later, while a superfluous category clutters the shelf permanently.

---

## 4. Never a category

| Candidate | Why not | Belongs to |
| --- | --- | --- |
| `italian`, `thai` | cuisine, not dish type | tag |
| `vegetarian`, `gluten-free` | diet | tag |
| `quick`, `under 30 minutes` | effort | tag |
| `christmas`, `barbecue` | occasion | tag |
| `oven`, `air fryer` | method or appliance | tag / tool |
| `chicken`, `pumpkin` | ingredient | ingredient search |
| `Nan's cookbook`, `BBC Good Food` | source | tag |
| `favourites`, `to try` | personal status | tag or cookbook feature |
| `Breakfast` | meal, not dish type | tag (under Axis A) |

---

## 5. Naming

- Noun, **singular**, title case: `Main`, not `Mains`
- No emoji, no prefixes, no numbering
- Established pairs joined with `&` are fine when they form one culinary role: `Sauce & Dip`
- No brand or source names

---

## 6. Checklist

- [ ] Does it answer the same question as every other category (§1)?
- [ ] Was an existing category checked as close enough?
- [ ] At least 15 recipes expected within a year?
- [ ] Browse rather than filter?
- [ ] Not a case from the forbidden table (§4)?
- [ ] Noun, singular, no emoji?
- [ ] Does the recipe stay at two categories or fewer?
